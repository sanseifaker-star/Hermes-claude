# Syncing Claude Code configuration across devices

"Перенести весь Claude Code проект" на практике разбивается на две разные
вещи:

1. **Код и история этой сессии/репозитория** — уже решено: всё лежит в
   `github.com/sanseifaker-star/Hermes-claude`. На любом устройстве, где вы
   авторизованы (в Claude Code / claude.ai), достаточно открыть/подключить
   этот репозиторий (или `git clone`), и вы увидите тот же код и сможете
   продолжить сессию — это обычный git-флоу, ничего дополнительно переносить
   не нужно.

2. **Личная конфигурация Claude Code** (`~/.claude/` на каждой машине) —
   custom slash-команды, skills, subagents, `settings.json` (permissions,
   hooks, model preferences). Это **не** синхронизируется само по себе,
   потому что физически лежит на каждом компьютере отдельно. Для этого —
   `scripts/sync-claude-config.sh` в этом репозитории.

## Что синхронизируется, а что — никогда

Скрипт **включает** в репозиторий:

- `~/.claude/settings.json` (без секретов, см. ниже)
- `~/.claude/commands/` — кастомные slash-команды
- `~/.claude/skills/` — кастомные skills
- `~/.claude/agents/` — кастомные subagents
- `~/.claude/CLAUDE.md` — глобальные инструкции

Скрипт **никогда не** включает и явно исключает:

- `~/.claude/.credentials.json` и любые OAuth-токены/API-ключи
- `~/.claude/projects/` — история переписки по проектам (может содержать
  секреты, приватный код, персональные данные)
- `~/.claude/shell-snapshots/`, `~/.claude/todos/`, логи

Если в `settings.json` обнаруживаются похожие на секреты значения (ключи,
токены), скрипт остановится и попросит вынести их в переменные окружения
вручную, а не коммитить.

## Использование

На **каждом** устройстве, которое нужно синхронизировать (Mac, Windows/WSL,
Linux) — запускаете сами, локально, не через эту облачную сессию (у неё нет
доступа к вашим личным машинам):

```bash
# Экспорт текущей машины в репозиторий:
./scripts/sync-claude-config.sh export

# git add / commit / push как обычно

# На другом устройстве — импорт:
git pull
./scripts/sync-claude-config.sh import
```

`import` создаёт резервную копию существующего `~/.claude` перед
перезаписью (`~/.claude.backup-<timestamp>`).
