# Security checklist — Hermes Agent self-hosted

Основано на публичном аудите безопасности hermes-agent:
[NousResearch/hermes-agent#7826](https://github.com/NousResearch/hermes-agent/issues/7826)
(v0.8.0, 4 critical / 9 high findings). Версия, которую вы установите, может
отличаться — сверяйте номер релиза с CHANGELOG репозитория и повторно
проверяйте, закрыт ли конкретный пункт.

## До установки

- [ ] Устанавливаете **не** под `root` напрямую — `install-hermes.sh` создаёт
      отдельного пользователя `hermes` без sudo-прав на систему в целом.
- [ ] Знаете свой Telegram user ID (получить у `@userinfobot`) — понадобится
      для DM pairing на шаге `hermes gateway setup`, чтобы бот отвечал
      только вам.
- [ ] Токен бота от `@BotFather` под рукой, но вводится **только на сервере**
      при интерактивной настройке — не в чате, не в git.
- [ ] Решили, каким терминальным бэкендом пользоваться. По умолчанию —
      `local` (bash хоста без песочницы, C1 из аудита). Рекомендуется Docker/
      Singularity/Modal бэкенд — меньше блast radius при компрометации,
      **но** аудит (C3) утверждает, что approval-проверки для контейнерных
      бэкендов сейчас тоже пропускаются безусловно. Контейнер снижает ущерб
      системе хоста, но не заменяет ревью действий агента.

## Во время установки (интерактивные шаги)

- [ ] `hermes setup` / `hermes model` — выбрать провайдера модели
      (рекомендация — Claude, см. README).
- [ ] `hermes gateway setup` — включить DM pairing / привязку к своему
      Telegram ID, а не открытый доступ.
- [ ] Проверить `hermes config --help` и `hermes --help` на факт актуальных
      флагов, соответствующих следующим пунктам аудита (имена флагов могут
      измениться между версиями — не полагайтесь на память, смотрите вывод
      команды на сервере):
  - **C1 / H7** — сузить/сэндбоксить shell и code-execution инструменты.
  - **C2** — включить read-deny-list, если доступен, либо ограничить рабочую
    директорию агента.
  - **H1** — `HERMES_YOLO_MODE` (или его текущий эквивалент) — **никогда не
    включать**. Это отключает все проверки безопасности.
  - **H2** — smart/auto-approval — отключить, approval должен требовать
    вашего явного подтверждения.
  - **H4** — safe-root для записи (в аудите фигурирует как
    `HERMES_WRITE_SAFE_ROOT`) — включить и ограничить рабочей директорией
    агента, а не всей файловой системой.
  - **H5** — hooks (`~/.hermes/hooks/`) — не подключать сторонние/непроверенные
    хуки.
  - **H6** — plugins — ставить только из проверенных источников.

## После установки

- [ ] Зафиксировать используемый commit hash `~/.hermes/hermes-agent`
      (`git -C ~/.hermes/hermes-agent rev-parse HEAD`) — не полагаться на
      автообновление без ревью (H9).
- [ ] Файрвол: разрешён только входящий SSH, всё остальное закрыто (Telegram
      работает через исходящий long-polling — входящие порты не нужны).
- [ ] `systemd` unit запускает агента от пользователя `hermes`, не `root`.
- [ ] Секреты (`.env`) лежат с правами `600`, владелец — `hermes`, не в git.
- [ ] Периодически (раз в 1-2 недели) — `hermes update` только после чтения
      changelog, не вслепую.
- [ ] Понимаете, что персональный ассистент с доступом к shell на вашем
      сервере — это фактически ключ от сервера. Не давайте боту делать то,
      что вы не готовы разрешить произвольному скрипту, скачанному из
      интернета, с вашими правами.
