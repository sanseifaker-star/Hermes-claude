# Server Health

## When to Use

Когда нужно оценить состояние сервера: плановый утренний отчёт, ответ на
вопрос «как там сервер», или проверка перед тем как что-то ставить и
запускать.

## Procedure

1. Диск: `df -h /`. Смотри процент занятости корня.
2. Память: `free -h`. Смотри доступную (available), не свободную (free) —
   это разные вещи, кэш отдаётся под нагрузку.
3. Аптайм и нагрузка: `uptime`. Load average выше числа ядер — сервер
   перегружен. У этой машины 1 ядро.
4. Свой шлюз: `systemctl --user status hermes-gateway --no-pager`.
5. Только если что-то из этого выглядит плохо — копай глубже:
   `du -xh --max-depth=1 /` для диска, `ps aux --sort=-%mem` для памяти,
   `journalctl --user -u hermes-gateway -n 50 --no-pager` для шлюза.

## Pitfalls

- Не путай `free` и `available` в выводе `free -h`. Судить надо по
  available.
- `df` без `-x` уходит в docker-монтирования и врёт по объёму.
- Пайпы и редиректы в командах здесь работают нормально — ограничение с
  потерей `|` и `>` касается только ручной вставки в терминал человеком,
  не твоих вызовов.
- Не перезапускай шлюз в рамках проверки. Ты работаешь внутри него —
  оборвёшь сам себя на середине.

## Thresholds

Тревога, если хоть одно:
- диск занят больше 80%
- available память меньше 200 МБ
- load average больше 2.0
- hermes-gateway не в состоянии active (running)

## Verification

Отчёт годен, если в нём есть конкретные числа со всех четырёх пунктов
процедуры. «Всё в порядке» без цифр — не отчёт: ты не проверил, а
предположил.

## Output

Всё в норме — одна строка с цифрами, без вступления.
Есть проблема — сначала что именно и насколько плохо, потом остальное.
